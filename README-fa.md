# warp-plus نسخهٔ واتاشی (v1.2.6-ws1)

این کیت warp-plus را از روی تگ رسمی `v1.2.6` می‌سازد و درست موقع ساخت، اصلاحات واتاشی را رویش اعمال می‌کند. کد اصلی دست‌نخورده دانلود می‌شود. فقط فایل‌های پوشهٔ `overlay` جایگزین می‌شوند و یک پچ کوچک هم روی `netstack/tun.go` زده می‌شود. اگر پروژهٔ اصلی بعداً این فایل‌ها را تغییر داده باشد، `build.sh` قبل از ساخت متوقف می‌شود و چیزی را خراب نمی‌کند.

## چه چیزهایی درست شد

| مشکل | فایل | issue در ریپوی اصلی |
|---|---|---|
| **نشت اصلی رم:** وقتی برنامه اتصال را می‌بست، رله منتظر سرور مقصد می‌ماند و اگر سرور ساکت بود، تا ابد منتظر می‌ماند. هر اتصال این‌طوری دو goroutine، دو بافر ۶۴ کیلوبایتی و یک اتصال TCP داخل gVisor را برای همیشه نگه می‌داشت. حالت سایفون درگیر نمی‌شد، چون آن‌جا فقط چند تونل ثابت از این رله رد می‌شوند. | `wiresocks/relay.go`، `wiresocks/proxy.go` | #43، #177، #237 |
| بافرهای TCP داخل gVisor برای هر اتصال ۱ مگابایت بودند و کوچک نمی‌شدند. یک تست سرعت کافی بود تا سرور فریز شود. حالا از ۱۲۸ کیلوبایت شروع می‌شوند و فقط وقتی برنامه واقعاً سریع می‌خواند، تا ۲ مگابایت بزرگ می‌شوند. | `patch-netstack.py` | #43 |
| اتصال UDP اگر هیچ بسته‌ای نمی‌گرفت، برای همیشه باز می‌ماند. سوکتش هم با بستن اتصال TCPِ صاحبش بسته نمی‌شد. | `socks5/server.go` | — |
| UDP روی آدرسی bind می‌شد که کلاینت فرستاده بود و خطای `cannot assign requested address` می‌داد. | `socks5/server.go` | #95، #206، #265 |
| بستهٔ UDP زیر بار خراب می‌شد (چند goroutine از یک بافر مشترک استفاده می‌کردند). مقصدهای دامنه‌ای هم به شکل `:443` شماره‌گیری می‌شدند. | `socks5/common.go` | — |
| فورواردر حالت gool با cancel متوقف نمی‌شد و روی سوکت بسته‌شده یک هستهٔ CPU را صددرصد مشغول می‌کرد. | `wiresocks/udpfw.go` | — |
| تست اتصال در هر تلاش یک transport جدید می‌ساخت و body پاسخ را نمی‌بست. تلاش ناموفق هم دستگاه وایرگارد را روشن جا می‌گذاشت. | `app/wg.go`، `app/app.go` | #242، #277 |
| خطای Accept بی‌وقفه تکرار می‌شد و ژورنال را پر می‌کرد. | `mixed/proxy.go`، `socks5/server.go` | — |

## ساخت روی سرور (ساده‌ترین راه)

```bash
unzip warp-plus-ws.zip -d /root/warp-plus-ws && cd /root/warp-plus-ws
bash build.sh --install
```

اسکریپت Go را از go.dev، کد را از تگ رسمی و ماژول‌ها را از پروکسی رسمی Go دانلود می‌کند. بعد `go vet` و تست‌ها را اجرا می‌کند (اگر gcc نصب باشد، با race detector)، برای amd64 و arm64 می‌سازد، باینری مناسب همین سرور را جای warp-plus پنل می‌گذارد و وارپ را دوباره بالا می‌آورد. نسخهٔ قبلی هم با نام `warp-plus.previous` نگه داشته می‌شود.

## ریپوی اختصاصی خودتان

کل این پوشه را در یک ریپوی جدید گیت‌هاب push کنید و یک تگ بزنید:
`git tag v1.2.6-ws1 && git push --tags`
GitHub Actions خودش می‌سازد، تست می‌کند و هر دو زیپ را همراه `SHA256SUMS` در Releases منتشر می‌کند. `build.sh` در انتهای خروجی‌اش دو خط آماده برای `common/packages.lock` چاپ می‌کند. فقط `OWNER/REPO` را عوض کنید تا نصب‌های تازه هم نسخهٔ سالم را بگیرند.

## چطور ثابت کنیم درست شد

این نسخه هر ۱۰ دقیقه یک خط در ژورنال می‌نویسد:

```bash
journalctl -u hiddify-warp -o cat | grep 'watashi stats' | tail -6
```

اگر نشت برطرف شده باشد، عدد `goroutines` و `heap_inuse` زیر بار بالا و پایین می‌رود، ولی روز به روز بالاتر نمی‌رود. برای بررسی دقیق‌تر می‌توانید pprof را هم روشن کنید: `WARP_PLUS_PPROF=127.0.0.1:6061`.

d=/opt/hiddify-manager/other/warp/warpplus
